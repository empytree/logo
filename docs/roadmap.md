# Последовательность внедрения

Публичная система — [empytree/logo](https://github.com/empytree/logo). Сайт empytree.com — самостоятельный потребитель. Код сайта, его Git-история, конфигурация и инфраструктура не входят в этот репозиторий.

Состояние на 24 октября 2026: репозиторий опубликован, версия 0.1.0 [внедрена](adoptions/0.1.0.md), публичные ресурсы проверены по HTTP. Полный генератор и отбор micro реализованы как кандидат 0.2.0; после коммита владельца нужны новый пакет и отдельное внедрение.

| Шаг | Результат | Условие завершения |
| --- | --- | --- |
| Публичный репозиторий | Создаётся владельцем, принимает текущую систему и документацию | Проверены файлы, политика прав и фактическая история коммитов |
| Первая версия | Ограниченный пул favicon и пакет ресурсов | Есть проверенный исходный commit и зафиксированная версия |
| Внедрение на сайте | Сайт получает пакет конкретной версии | Локальные проверки пройдены; владелец выполняет свой релизный процесс |
| Запись о внедрении | Отдельный коммит системы знака | Зафиксированы реально внедрённая версия, дата, область применения и публичные подтверждения |
| Полный генератор | Независимые верхи, рты и рамки | Реализованы и проверены правила сочетаний, а не только перечислены 144/288/432 варианта |
| Отбор micro | Группы вариантов и причины исключений | Грязные/неразличимые 16 px сочетания исключены до случайного выбора |
| Следующее внедрение | Сайт получает новую версию; применение логотипа расширяется | Отдельные проверка, версия, выкладка и запись внедрения |

Первое внедрение использует build-time генерацию готовых ICO и выбор одного из 24 сочетаний на загрузке документа. Большая музыкальная матрица не вводится на сайт раньше генератора и отбора micro. Будущее расширение применения может включать страницы проектов и более крупные брендовые поверхности; оно не меняет принятые конструктивные признаки автоматически.

## Правило источника

Публичный репозиторий задаёт геометрию, алгоритм разнообразия, допустимые сочетания и экспорт. Сайт содержит копию выпущенного пакета и его provenance-файл. Ручные исправления рисунка только на сайте не становятся новой версией системы: сначала меняется источник, затем потребитель обновляет пакет.

Не загружать исполняемый JS с GitHub на каждой странице. Для потребителя нужны локальные статические ресурсы конкретного выпуска. Отсутствие внешней зависимости в runtime сохраняет favicon при недоступности GitHub.

## Micro-отбор следующей версии

Предусмотреть таблицу разрешений по оптическому размеру и группы причин: столкновение с рамкой, слияние деталей, исчезновение паузы, недостаточный контраст, дублирование другого силуэта. Отбрасывать сочетание до перемешивания пула; не заменять его неожиданным другим лицом после выбора. Сохранить фиксированный fallback, проверять плотности 1×/2×/3× и показывать реальный растр вместе с увеличением.

Реализация и причины — в [генераторе](generator.md). Текущий отбор допускает 40 открытых/закрытых сочетаний, 20 открытых по умолчанию; 248 исключены. Дополнительные причины можно вводить после воспроизводимого исследования, не объявляя заранее найденными. Расширение применения за пределы favicon остаётся следующим самостоятельным этапом.
