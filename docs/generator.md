# Полный генератор и отбор micro

[English](en/generator.md) · [Генератор без сервера](../examples/generator.html) · [Первое внедрение](adoptions/0.1.0.md)

Версия 0.2.0 — следующий кандидат на выпуск. На сайте внедрена 0.1.0. Принятые `from-inset`, `character`, размеры рамки и уменьшение micro-головок сохраняются. Прежние стрелки с шестью геометрическими ртами воспроизводятся побайтово одинаковыми SVG.

## Матрица

`tools/system.mjs` независимо выбирает:

| Параметр | Варианты |
| --- | --- |
| Готовая пара глаз | `arrows`, `beam`, `separate`, `mixed` |
| Рот | `flat`, `rise`, `fall`, `corner-left`, `corner-right`, `down`, `rest8`, `rest4`, `rest2` |
| Бока | `none`, `left`, `right`, `both` |
| Рамка | `open`, `closed`, `crease`; последняя только display |

`mixed` — короткая горизонтальная вязка у левой ноты и отдельный флажок правой. Это не независимый выбор каждого глаза. Половинная пауза располагается **над** короткой опорной линией: без неё или при расположении под ней меняется считывание длительности. Знак не является полной исполняемой нотной записью.

Реализованы **432** выражения display и по **288** кандидатов compact/micro. Оптические версии, цвета, форматы и плотности не умножают число выражений. Запрос `crease` для малой версии вызывает ошибку; незаметной подмены на открытую рамку нет. Исторический `mark({family: ...})` сохранён; новый API — `renderMark({eyes,mouth,frame,dent,optical})`.

## Почему 16 px получает меньший набор

Политика micro редакции 1 допускает **40 из 288** сочетаний открытой/закрытой рамки. Из них **20** — с открытой рамкой для пула сайта по умолчанию. Исключены **248**. В разрешённом наборе представлены все четыре верха. Исторический пул 24 внедрённой версии 0.1.0 не переписывается задним числом.

Алгоритм отбора выполняется при сборке:

1. Рамка, глаза и рот отдельно растеризуются в прозрачные слои при плотностях 1×, 2×, 3×: 16, 32, 48 физических пикселей.
2. Пиксели с alpha ≥64/255 включаются в маску. Для каждой пары слоёв измеряется евклидово расстояние между ближайшими центрами занятых пикселей.
3. Нужно расстояние не меньше `density + 1` физических пикселей для рамки/глаз, глаз/рта и рамки/рта на каждой плотности.
4. Вся группа `rest4` в micro исключается: повороты четвертной паузы превращаются в неоднозначный фрагмент. Другие конфликтные группы определяются измерениями, а не произвольными запретами по имени.
5. Из оставшихся сохраняется один представитель одинаковых пороговых силуэтов 16 px в фиксированном порядке перебора. Это не доказательство различимости человеком; проверки всех плотностей остаются обязательными.
6. Перемешивается уже отобранный список. Пустая запрошенная группа сохраняет постоянный fallback, а не заменяется неожиданным другим лицом.

Порог — консервативное проектное правило, не измеритель красоты и не универсальная сертификация читаемости. [Полный отчёт](research/micro-policy.json) хранит причины, расстояния по плотностям и каждый запрет. [Лист реальных пикселей](brand/matrix-micro.png) включает исключённые образцы; [крупный лист](brand/matrix-display.png) показывает все пары верх/низ. Визуальная проверка подтверждает потерю деталей пауз и столкновения; отображение во вкладках разных браузеров может отличаться.

Display применяется от 64 CSS px, compact — 21–63, micro — 16–20. ICO использует micro-геометрию при 16/32/48 физических px, а не compact-рисунок в слоях высокой плотности.

## Воспроизведение

```sh
npm ci
npm run verify
npm run generate -- --eyes mixed --mouth rest2 --dent left --size 128 --output .local/mixed.svg
npm run generate -- --eyes beam --mouth flat --size 16 --format png --output .local/beam.png
```

CLI принимает 16–4096 px; SVG без `--output` выводится в stdout, для PNG путь обязателен. Запрещённый micro-экспорт завершится ошибкой. Явный `--study` создаёт исследовательский образец с предупреждением и не разрешает использовать его в favicon-пуле.

`examples/generator.html` открывается прямо с диска: 1008 оптических рисунков, настоящие PNG 16 px, причины исключений, случайный разрешённый выбор, скачивание SVG и сохранение параметров во фрагменте URL. Сервер, API, внешние шрифты и сеть не нужны. Первая галерея сохранена отдельно.

## Следующее внедрение

После коммита владельца и при чистом рабочем дереве:

```sh
npm run export:site -- --commit FULL_40_CHARACTER_HEAD_SHA
```

`--development` создаёт только локальный пакет с null вместо исходного коммита. Пакет 0.2.0 включает 40 разрешённых ICO, постоянный fallback, Apple icon, PNG 96, selector и ограниченный manifest. По умолчанию выбираются 20 открытых вариантов. `data-frames="open,closed"` разрешает также закрытые. `data-eyes`, `data-mouths`, `data-dents` сужают уже отобранный набор и не вводят запрещённые сочетания.

Selector содержит готовый allowlist, не запрашивает manifest и ничего не рисует в браузере. Fisher–Yates перемешивает sessionStorage-мешок; каждый вариант посещается до повторного цикла, немедленный повтор на границе исключён. Изменение пула сбрасывает несовместимое состояние. Без storage нет гарантии отсутствия повторов между загрузками.

Provenance, версионные локальные URL и no-JS сохраняются по [правилам подключения](en/usage.md). Старый ограниченный экспорт доступен как `npm run export:legacy`; для следующего внедрения используется `export:site`. Запись внедрения 0.2.0 создаётся только после реального обновления сайта.
